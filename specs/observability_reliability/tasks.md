## How to read this file

**`[ARM]` marks a task whose prose makes a countable claim** — a count, an identity, an ordering or an absence. It is not done until the named test has been **seen to fail** under the named mutation (CLAUDE.md "Arming protocol": backup into `.arm/` with its `sha256`, mutate, run the ONE test with a process-group timeout, record the failure verbatim — its message must name the claim — restore by `cp`, `cmp`, clear `__pycache__`/`.mypy_cache`, re-run green). The arming record lives in `progress/impl_observability_reliability.md`. An `[ARM]` box whose mutation survives is reported, never ticked.

**`[MEASURE]`** marks a task whose output is a recorded observation from a real container or process, quoted verbatim, on which a later task depends.

**`[LEADER]`** marks a task the implementer does not do (`.env.example`, the developer `.env`, `infra/`, compose): the implementer stops and names the keys; the leader does it.

**Three mutation families.** Deletion; corruption of a field the test supplied; substitution of a real sibling identifier (topics, consumer tokens, subjects, settings variables, check names, client ids, metric names). A substitution's failure must name what was broken; if the sibling is unset and a default answers, the failure is for the wrong reason.

**Standing rules.** Every wait is `asyncio.timeout(...)` with a message naming the claim, paced explicitly, synchronised on terminal evidence. Every test passes with the developer infrastructure down. Every DLQ read selects by the test's own `eventId`/`correlationId`, with a decoy published first on the same topic. Every capture over a shared sink (in-memory exporter, metric reader, `caplog`) is scoped to what the test produced. Header instants in fixtures are pairwise distinct (entry, first failure, final failure, `occurredAt`). A test's name is a claim: if what it asserts narrows, the name changes. Tick as you go; reword a box whose delivered shape differs **on the box**.

**Bounds.** May touch: the files of `design.md` §9.3 and §10, the tests named below, `tests/architecture/{test_kafka_client_confinement,test_kafka_client_ids,test_composition_env_reads,test_outbox_copy_parity,test_dependency_freedom}.py` where a task says so, new modules under `tests/architecture/` and `tests/observability/`, root `conftest.py` (the session OTLP blank and the `.dlq` fixture topics), each service's `pyproject.toml` dependencies through `uv add --package`, `uv.lock`, `services/orders/alembic/versions/0003_*.py`, and `specs/shared/test-matrix.md` **Status cells** of `R16`, `R29`, `R56` – `R60`, `R62` only. Must not touch: any other byte of `specs/shared/`, `infra/`, compose files, `.env.example`, `.env`, `n8n/`, `apps/web/`, `packages/shared_kernel`, `packages/cqrs`, `feature_list.json` beyond the single status line of S8.7.

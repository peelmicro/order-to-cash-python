## 2. Local requirements reused from #8 (and #7)

**OR1.** WHEN a fact consumed by `orders.saga`, `projector` or `notifications` causes its processing to raise after the envelope guard has passed, THE SYSTEM SHALL retry that processing in line up to a configured maximum number of attempts (`FACT_RETRY_MAX_ATTEMPTS`, default `3`) with exponential backoff (`FACT_RETRY_BACKOFF_MS`, default `500` ms, doubling), and on exhausting them SHALL publish the **unmodified original record value** to `<source-topic>.dlq` carrying `asyncapi.yaml`'s `DeadLetterHeaders` (`x-failed-consumer`, `x-attempts`, `x-error`, `x-original-topic`, `x-first-failed-at`, `x-failed-at`, `x-event-type`, and `traceparent` when a span is active), and SHALL then return normally so that the source offset commits. *(Refines `R16`'s "configured maximum" with the trilogy's policy. The header instants follow `SA-3`, `asyncapi.yaml:2227-2232`.)*

**OR2.** THE SYSTEM SHALL realise `OR1`'s retry-then-dead-letter wrapper as **one canonical module copied** into every fact-consuming service, parity-guarded, and the guard SHALL require the copy from every service that owns a fact consumer and from no other.

**OR3.** WHEN a `saga_commands` row transitions into `parked` for the **first** time, THE SYSTEM SHALL, in addition to the existing park bookkeeping (`SO5`, unchanged): (a) append exactly one `order.saga_failed.v1` for that order through the outbox, carrying the command, the accumulated attempt count and the last error; and (b) WHERE the row stores the envelope of the fact that triggered it, publish that envelope to its source topic's `.dlq` with `DeadLetterHeaders` naming the `orders.saga` consumer. THE SYSTEM SHALL perform (a) and (b) **at most once per row** and SHALL NOT alter `SO5`'s indefinite capped-backoff retry.

**OR4.** WHEN a message is published on the RPC transport or the fact stream, THE SYSTEM SHALL inject the current W3C `traceparent` (and `tracestate` when set) into its headers; WHEN such a message is received, THE SYSTEM SHALL extract that context and continue the trace (same trace id, a fresh span whose parent is the injected span); WHERE no span is active at publication, THE SYSTEM SHALL emit no `traceparent` header at all.

**OR5.** THE SYSTEM SHALL export spans and metrics over OTLP to the provisioned OpenTelemetry Collector, SHALL expose no per-service Prometheus scrape endpoint, and SHALL distinguish services by the OTel `service.name` resource attribute.

**OR6.** THE SYSTEM SHALL serve `GET /health/live` and `GET /health/ready` on every service, each answering `openapi.yaml`'s `HealthResponse`; each service's readiness SHALL consult exactly the dependencies it has, and every probe SHALL be a real reachability call bounded by an explicit timeout, never a cached value.

**OR7.** THE SYSTEM SHALL emit every log record as a single-line JSON object carrying the trace id and span id, and — on every record produced while handling an inbound HTTP request, an RPC request, a consumed fact, a saga command dispatch or an outbox relay of one row — that unit of work's `correlationId`; WHERE no span is active, THE SYSTEM SHALL omit the trace fields rather than render them empty. *(Refines `R58`'s "every line produced while handling a request, a command or a fact": a line produced outside any unit of work — a boot line, a library's background heartbeat — is JSON and carries no `correlationId`, because none exists; none is fabricated.)*

**RI1.** THE SYSTEM SHALL persist, for every accepted `orders.create` that supplies a `requestId`, that `requestId` against the created order under a uniqueness constraint that admits at most one order per `requestId` and any number of orders that supply none.

**RI2.** WHEN a valid `orders.create` (one the handler does not refuse before the lookup: a non-zero `orderDiscount` is refused first) carries a `requestId` for which a committed order exists, THE SYSTEM SHALL perform no reference-data resolution, no stock check and no write, and SHALL return that order's original reply. *(Order of checks: #7 refuses a non-zero `orderDiscount` before the lookup, `apps/orders/src/application/place-order.handler.ts:68-77`, and #9 follows it; #8 looks up first, `src/Orders/Application/Commands/PlaceOrderCommandHandler.cs:39-50`, so for a known `requestId` with a non-zero `orderDiscount` #8 replays and #7 and #9 refuse. Guarded by `test_ri2_a_known_request_id_with_a_non_zero_order_discount_is_refused_and_not_replayed`.)*

**RI3.** WHERE two `orders.create` requests carrying the same not-yet-committed `requestId` are processed concurrently, THE SYSTEM SHALL let exactly one commit an order, SHALL detect `RI1`'s uniqueness violation in the other — distinguished from a violation of any other unique index — and SHALL resolve that request to the winning order's reply by re-reading it, never to an error and never to a second order.

**RI4.** WHERE `requestId` is omitted, THE SYSTEM SHALL place a normal order, performing no lookup against `RI1`'s constraint.

**RI5.** WHERE `orders.create` supplies a `requestId`, THE SYSTEM SHALL use it as the `causationId` of the resulting `order.placed.v1`; WHERE it is omitted, THE SYSTEM SHALL mint a fresh causation id. *(#7 `apps/orders/src/application/place-order.handler.ts:143, 205-211`; adopted by #8 as `RI5`. #9 today mints a fresh id unconditionally, `services/orders/src/otc_orders/application/commands/place_order.py:166`: a change to shipped behaviour, so it carries its own id and task.)*

## 3. Local requirements new in #9

**OR8.** IF the publication of a dead letter is not acknowledged by the broker, THEN THE SYSTEM SHALL NOT commit the source record's offset, so that the record is delivered again. *(Narrows `R16`'s "acknowledge the original fact": the acknowledgement follows a durable dead letter, never precedes it. #8 had the property by the order of its statements and no requirement; #9 makes it a claim because the Python subscriber's commit is explicit, `kafka_fact_subscriber.py` `_consume`.)*

**OR9.** THE SYSTEM SHALL record exactly five metric instruments under these names and attribute keys, each declaring **no unit**: `otc_request_latency_ms` (histogram, `endpoint`), `otc_fact_processing_latency_ms` (histogram, `consumer`), `otc_saga_completion_ms` (histogram, `outcome` ∈ {`completed`, `cancelled`}), `otc_outbox_lag_ms` (gauge, no attribute), `otc_dlq_depth` (gauge, `topic`), so that the series Prometheus stores through `infra/otel-collector` are the names `infra/grafana/dashboards/order-to-cash-overview.json` queries. *(Refines `R59`, which names quantities and no identifiers. The unit clause is measured, not assumed: design §6.1.)*

**OR10.** WHEN the sweeper dispatches a `saga_commands` row that recorded a trace context at enqueue, THE SYSTEM SHALL continue that trace rather than start a new one; WHERE the row recorded none, THE SYSTEM SHALL start a new root and fabricate no parent. *(Refines `R56`'s "every RPC command … under a single trace identifier" for the only command path that runs outside the fact's context. Gate row G3.)*

**OR11.** WHEN a saga command is resolved `rejected` by a terminal `RpcError` (feature 42), THE SYSTEM SHALL append no `order.saga_failed.v1` and publish no dead letter, and SHALL emit exactly one ERROR record for it carrying `correlationId` (the order id), the command, the `RpcError` code and the trace id. *(A recorded decision, not a refinement: `specs/shared/` decides it — `domain-model.md:475` defines `order.saga_failed.v1` as a command that "exhausted its in-line retries and parked", `R29` triggers on "times out or returns a transport error", and `saga.md:237-240` calls a `PRECONDITION_FAILED` refusal of `despatch.create` "not a saga failure: no retry, no dead-letter, no `order.saga_failed.v1`". Gate row G2.)*

**OR12.** WHEN `orders.cancel` enqueues a compensation command, THE SYSTEM SHALL store no triggering envelope for it, so that its first park appends `order.saga_failed.v1` (`OR3` (a)) and publishes no dead letter. *(Conformance with `asyncapi.yaml`'s `DeadLetterRecord`, whose payload is an `Envelope` whose `eventType` must match `^[a-z]+\.[a-z_]+\.v[0-9]+$` (`:2171`) on a channel of "facts from `otc.orders.facts.v1`" (`:187`). #7 and #8 store and dead-letter a synthetic `orders.cancel.requested` envelope, which matches neither. This **reverses acceptance item 12's mechanism**; gate row G1.)*

**OR13.** WHEN the Gateway process receives its exit signal while server-sent event streams are open, THE SYSTEM SHALL end every open stream normally before the graceful-shutdown bound and SHALL emit no ERROR record during the shutdown. *(Acceptance item 13; `progress/review_gateway_sse_push.md` N1.)*

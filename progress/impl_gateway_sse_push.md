## 3. Decisions the three items left open

* **Overflow policy: a client whose queue fills is disconnected, and resumes from its `Last-Event-ID`.** #7 ignored back-pressure (`stream-hub.ts:37,47`, an unbounded RxJS `Subject`; `stream.controller.ts:69-73`, `res.write` per frame). #8 bounded each connection at 256 and **dropped the oldest** (`StreamHub.cs:35,55-62,82-90`). Drop-oldest lets the client's `Last-Event-ID` step over frames it never received, which `openapi.yaml` does not allow ("A frame may repeat after a reconnect": at-least-once, never "may be missing"). #9 marks the subscription `overflowed` and the route ends that response; the browser's `EventSource` reconnects with the last id it processed and the replay buffer returns what it had not seen. That is complete only while the frames the queue held plus the frames published during the reconnect are fewer than the buffer (with a queue equal to the buffer, or a burst during the reconnect, the client's cursor can be evicted: the reply is `resumed: false` and the client re-fetches, which the contract allows; Round 2, N3), so `SseSettings` refuses `GATEWAY_SSE_CLIENT_QUEUE_CAPACITY > GATEWAY_SSE_BUFFER_CAPACITY` at boot (armed K1). `publish` never waits on a subscriber (armed D1, D2). This is a difference from #8 with a stated reason (the contract's delivery guarantee), not a taste; the leader may overrule it, and the cost of reverting is one branch in `Subscription.offer`.
* **Cursor minting under concurrency.** #8 needed `Interlocked.Increment` because two NATS loops ran on the thread pool. #9 has one event loop; `CursorGenerator.next` and `StreamHub.publish` are plain synchronous methods with no `await`, so two tasks cannot interleave inside them. The guard is two-fold and armed (F1, F2): the method must not be a coroutine function, and 1000 tasks that yield between calls still get 1000 distinct, ordered cursors, and the replay buffer's order equals the cursor order. **Not guarded, and said so:** a second thread calling `next`. Nothing calls it from a thread (the nats-py callbacks and uvicorn run on the loop); uvicorn runs one worker (`__main__.py`, as for the login limiter).
* **Frame writer: raw ASGI, not `StreamingResponse`.** Two reasons, both measured: `StreamingResponse` appends `; charset=utf-8` to a `text/*` media type (the contract's header is `text/event-stream`; armed B6), and a generator's `finally` runs only when the generator is closed, which is not deterministic when the task is cancelled inside `send` (a client that stopped reading). `EventStreamResponse.__call__` takes and releases the subscription in one `try`/`finally`.
* **`ping` cadence** is fixed (a deadline that advances by the interval, `asyncio.timeout_at`), as #7 (`stream.controller.ts:75-79`) and #8 (`StreamEndpoints.cs:102`) do, not "N seconds since the last frame".
* **Data forwarded untouched.** As #8 (`NatsStreamSignalSubscriber.cs`, bytes forwarded, order id from the subject) and unlike #7 (`nats-stream-signal.adapter.ts:31-43`, decode then re-serialise). #9 adds one check neither had: a payload that spans more than one line is refused (a newline inside `data:` would end the SSE frame early and let the rest be read as fields); armed E2.
* **Readiness**: a third check `streamSignals` (a dead subscriber task takes `/health/ready` down); `HealthResponse.checks` is `additionalProperties`, so the contract allows it. Three existing tests that listed the two checks were extended (`test_gateway_composition.py`).

## 14. What surprised me

* `httpx.ASGITransport` waits for the whole body. A guard that must fail when the stream is wrongly public **hung** instead (H1, killed at 180 s) until each sweep request was bounded. Any later test that sends a request to `/orders/stream` through `harness.client` will hang the same way: use `asgi_stream`.
* A pair-set population test passes when another source produces the same pair: arm P1 (read-model outage -> 500) survived until four source-specific sentinel checks were added.
* `StreamingResponse` is not enough for SSE here (the `charset` parameter on `text/event-stream`; a generator's `finally` is not deterministic when the task is cancelled inside `send`).
* uvicorn waits for open responses before running the lifespan's shutdown; without `timeout_graceful_shutdown` the first browser tab would hang a stop signal. It then logs the cancelled stream as an `Exception in ASGI application` (noise).
* Feature 25's `test_gateway_docs.py` used `/orders/stream` as the one thing "only the committed document has"; mapping the route made that false (it now uses `x-sse-events`). Likewise `test_openapi_conformance.py`'s exclusion set is empty and the population is 18 of 18.
* The first draft of the weak form of the heartbeat test failed for the wrong reason when the ping was deleted (the client's own read timeout fired, not the relay). The per-frame read bound is now 4x the idle window, so what ends a ping-less stream is the relay closing it.
